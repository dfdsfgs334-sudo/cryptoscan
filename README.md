# CryptoScan Journal

Дневник трейдера с автозагрузкой всей истории сделок Binance (Spot + USDⓈ-M Futures).

**Фронтенд** — один файл `trading-journal.html` (можно хостить на GitHub Pages или открыть локально).
**Бэкенд** — Supabase: Postgres + Auth + две Edge Functions.

## Что умеет

- **Дашборд**: чистый PnL, win rate, profit factor, матожидание, средний профит/лосс и R:R, макс. просадка, серии, зелёные/красные дни, оборот, комиссии, funding.
  Графики: кривая капитала, PnL по дням, по монетам, по дням недели, по часам, long vs short, тепловая карта активности за год.
- **Сделки**: все ордера (fills сгруппированы по orderId) с PnL, фильтрами, поиском по тегам/сетапам, сортировкой и экспортом в CSV.
- **Журнал**: к каждой сделке — сетап, теги, эмоция, ошибки, оценка исполнения, заметки, скриншот.
- **Аналитика журнала**: PnL и win rate по сетапам, тегам, эмоциям, ошибкам, оценкам, длительности позиций.
- **Календарь**: PnL по дням и неделям.
- **Импорт CSV/XLSX** из экспорта Binance — для истории старше, чем отдаёт API. Дубликаты отсеиваются.

## Как работает загрузка истории

| Рынок | Источник | Глубина |
|---|---|---|
| Spot | `GET /api/v3/myTrades`, пагинация `fromId` | **вся история** |
| USDⓈ-M | `GET /fapi/v1/income` → торгуемые символы, затем `GET /fapi/v1/userTrades` окнами по 7 дней | ~6 месяцев (ограничение Binance) |
| Funding | `GET /fapi/v1/income` | ~6 месяцев |

У Binance нет эндпоинта «все мои сделки» на споте, поэтому **первая синхронизация проверяет каждую пару биржи** (~3000 пар, с учётом лимитов API ~10–15 минут).
Функция `sync` работает порциями по ~45 секунд, сохраняя очередь и курсоры в БД; интерфейс вызывает её повторно, пока не закончит. Прогресс не теряется: можно закрыть вкладку и продолжить потом.
Следующие синхронизации быстрые: проверяются только пары, где уже были сделки, и монеты на балансе.

Фьючерсы старше 6 месяцев: Binance → Orders → Futures Order → Trade History → Export, затем загрузить файл во вкладке «Binance и импорт».

## Установка

1. Установи [Supabase CLI](https://supabase.com/docs/guides/cli) и привяжи проект:
   ```bash
   supabase login
   supabase link --project-ref jklcjlqpzzmfyvbvgohc
   ```
2. Создай таблицы:
   ```bash
   supabase db push
   ```
   (или выполни `supabase/migrations/20261106000000_crypto_journal.sql` в SQL Editor).
3. Задай ключ шифрования API-секретов (любая длинная случайная строка, **не теряй её** — без неё сохранённые ключи не расшифровать):
   ```bash
   supabase secrets set KEYS_ENCRYPTION_SECRET=$(openssl rand -hex 32)
   ```
4. Задеплой функции:
   ```bash
   supabase functions deploy save-keys
   supabase functions deploy sync
   ```
5. Открой `trading-journal.html`, зарегистрируйся, вставь API-ключ Binance (**только чтение**, без права вывода — такие ключи функция отклоняет) — первая синхронизация запустится сама.

## Регион

Binance блокирует запросы из США (HTTP 451). Фронтенд вызывает функции с заголовком `x-region: eu-central-1`, чтобы они выполнялись во Франкфурте. Регион меняется в константе `FUNCTIONS_REGION` в `trading-journal.html`.

## Безопасность

- API Secret шифруется AES-256-GCM в edge-функции; клиенту колонка `secret_enc` недоступна (column-level grants + RLS).
- Ключи с правом вывода средств не принимаются.
- Все таблицы под RLS: пользователь видит только свои данные.

## Как считается PnL

- **Spot** — метод средней цены входа по каждой паре; комиссии в базовой/котируемой монете учитываются в цене, комиссии в BNB вычитаются отдельно.
- **Futures** — `realizedPnl` от Binance минус комиссии; funding учитывается в общем PnL и кривой капитала.
- Пары с котировкой не в долларах (ETH/BTC и т.п.) и комиссии в BNB пересчитываются в $ по **текущему** курсу — это приближение.
- Продажа монет, купленных вне загруженной истории (депозит, конвертация, Earn), не даёт PnL — такие ордера помечены `*`.
